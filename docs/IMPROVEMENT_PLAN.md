# Bounded improvement plan before freeze

Keep the proven local app and Qwen profile as fallback. No speculative features or new weight downloads. Stop work at the planned 10:30pm Pacific freeze and rebuild/recheck the source candidate.

1. **Resource/policy gate before cluster inference.** Existing CPP account permits one GPU but only4GiB host RAM/job. Proposed14B BF16 pilot needs an administrator-approved higher-memory allocation (proposed one GPU/four CPUs/64GiB/30min) and current confirmation that finite scheduled inference/private access are allowed. No job, project upload, download or tunnel until that gate is satisfied. Current read-only discovery does not establish hosting permission.
2. **Development quality check only after that gate.** Verify existing model index, shard checksums/revision and runtime architecture support before loading. Use one short request, single sequence, small context/output budget and inspect actual VRAM/host memory inside the scheduler allocation. Preserve failures and latency. Compare only on explicitly development-labelled examples; make no held-out claim from existing six cases.
3. **Fix only reproducible application defects.** Prioritize dropped input, stale output/export, visible provenance and error recovery. Add a regression that fails first for an actual defect, then rerun affected checks and all57 tests. Do not hardcode case names, required labels or semantic thresholds into guards to improve an inspected score.
4. **Separate final readout if time permits.** Freeze new inputs and labels before the selected final run; keep labels/scoring out of the model request. Prefer independent human label review; if absent, say single-analyst exploratory. Seal inputs, prompt, runtime/settings and raw outputs before scoring. Run once, report false support/accusation/abstention/errors and latency separately, and manually inspect citation relevance. Do not tune on this new set afterward. Any failure remains part of the result.
5. **Freeze and submit.** No improvement is worth losing the working demo. If resource/policy gate remains blocked, use the already-working local model honestly, rehearse real latency and publish only the owner-approved audited source/video. See RELEASE_CHECKLIST.md.
